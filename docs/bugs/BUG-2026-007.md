# BUG-2026-007: Merging before result verification falsely blocks completed work

## Reproduction and evidence

BE-01 delivered PR #17 from `feature/slack-6e05ab1dd2cd5f09` to `main`.
GitHub reports it merged at 2026-11-16 13:50:36 UTC as `981e322`; both CI jobs
passed. The worker's saved result instead reported `GitHub did not verify the
PR branch/base/state`, with no PR URL. `verify_pr` required state OPEN.

Regression tests first failed because the valid merged result became Blocked and
the identity verifier rejected MERGED. With the fix, the same execution produces
Done, preserves the PR and test evidence, publishes to updates and retains its
durable claim. A second execute call does not rerun implementation. Separate
assertions retain rejection of wrong repositories/branches/bases and CLOSED PRs.

## Resolution

Accept MERGED only after the existing identity checks. The agent still returns
only `pr_ready` or `blocked`; the worker derives `done` from GitHub state itself.
This does not merge a PR or infer passing checks from a merge.

The original BE-01 task in Phase 2 and its existing Slack notification were
corrected after independent GitHub verification. The saved ledger result now
reports Done, retains the original failure reason for diagnosis and preserves
the claim. Corrections ran under the existing worker lock. No new implementation
run was started. Runtime installation of the general fix awaits the reviewed PR;
see the activation handoff.
