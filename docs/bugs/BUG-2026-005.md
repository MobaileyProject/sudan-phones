# BUG-2026-005: First executor run cannot trust its task checkout

## Reproduction and evidence

List item Rec0CJT6V0PCY was claimed on feature/slack-5b477b0fa1a12cf4.
The first real agy implementation session attempted a global safe.directory change
before git status/worktree inspection. Headless policy denied that command and
the worker correctly marked the task Blocked and delivered a dev-chat notification.
The worktree stayed clean and no PR existed. The service-level safe.directory
environment did not include the task checkout.

The environment regression returned missing instead of trusted before the fix.
The user then explicitly authorized --dangerously-skip-permissions. Its opt-in test
also failed before support was added. Both tests cover the actual child-process
boundary; the permission opt-in applies only to implementation, not message writing.

## Resolution

The worker now passes task Git trust through its child environment and supports
the explicit per-worker opt-in. Global Git/agy settings remain untouched. The first
blocked attempt is preserved; a fresh Ready item is used for the deliberate retry.
Full test and live retry results are recorded in docs/STATE.md.
