# BUG-2026-008: Query parsing bypassed the P2 JSON error contract

## Reproduction and evidence

Review of the unmerged P2 implementation found that exceeding Django's query
field limit raised from request.GET outside middleware finalization. With debug
off, the response was HTML 400 without X-Request-ID or no-store; debug rendering
could raise again. Separately, `?format=xml` returned 404 before strict validation.

Tests reproduced both failures before the fix. The field-limit test lowers the
configured limit to two and sends three fields in both DEBUG modes, so it covers
the real parser boundary without a huge fixture. The existing strict-query table
now includes the reserved format name for both config and bundle.

## Resolution

Establish the locale from headers first, catch TooManyFieldsSent and finalize a
sanitized JSON error through the same trace/cache-header path. Disable DRF's
format query override; clients select JSON via Accept, and unknown query keys
receive the documented validation error. No query values are logged or echoed.
