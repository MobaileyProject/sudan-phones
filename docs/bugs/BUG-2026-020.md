# BUG-2026-020: Avoidable query-per-listing in public search serialization

## Description
Public `listing_data(listing)` executed an unnecessary `order_by("position")`
and `select_related("asset")` query on `listing.media_links` even when the
caller (`visible_listings()`) had already prefetched media links. This caused N+1
queries scaling with page size.

## Reproduction
Observed in `backend/core/tests/test_public_performance.py`:
`test_search_media_query_count_does_not_grow_with_page_size` failed before the fix.

## Resolution
In `backend/core/listings/services.py`, `ordered_media(listing)` now inspects
`getattr(listing, "_prefetched_objects_cache", {})` and reuses prefetched media
links if present, sorting in Python by position. The regression test now verifies
that query counts remain constant regardless of page size.
