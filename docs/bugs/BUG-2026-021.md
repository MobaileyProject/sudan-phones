# BUG-2026-021: Eager S3 client initialization for public CDN URLs

## Description
`R2Storage.__init__` required full R2 credentials and instantiated a `boto3`
S3 client even when only generating public CDN URLs (`storage().public_url(key)`).
In environments without R2 write credentials or during read-only public listing
serialization, this caused needless overhead or initialization failures.

## Reproduction
Observed in `backend/core/tests/test_public_performance.py`:
`test_public_cdn_urls_work_without_s3_credentials_or_client_construction` failed
before the fix.

## Resolution
In `backend/core/media/storage.py`, `self._client` is now initialized lazily via a
`@property client`. `public_url(key)` only requires `settings.R2_PUBLIC_DOMAIN` and
does not access `self.client`, allowing public listing serialization without S3
credentials or client construction.
