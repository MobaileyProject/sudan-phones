# BUG-2026-002: Slack publication retries repeat writes and block other jobs

## Reproduction and evidence

Independent review of the uncommitted initial worker found publication recovery
defects. Reproduced locally with Python 3.14 standard-library tests and temporary
SQLite ledgers; no Slack credentials or production rows were involved.

Queue two results; let the first row update succeed but its message fail. A retry
called the List update again, potentially reverting a newer human/merged status.
Separately, let the first row update fail: the exception prevented publication of
the second valid result. New Ready work was downstream of the same exception.
Expected: a successful List mutation is checkpointed; unrelated jobs continue.

The two named regression tests failed against the initial implementation before
the fix. The corrected loop checkpoints List mutation and catches errors per job.
An ambiguous network failure before the local checkpoint remains a recovery limit;
there is no transactional compare-and-swap across SQLite and Slack.

## Resolution

Fix and tests are part of the Slack automation PR on feature/slack-agent-automation.
Run `python3 -m unittest discover -s tests -p test_slack_automation.py -v` and
`make check`; the final command results are recorded in docs/STATE.md.
